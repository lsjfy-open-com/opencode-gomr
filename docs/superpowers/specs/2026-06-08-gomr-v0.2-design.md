# GOMR v0.2 Design

## Summary

Upgrade GOMR from a lightweight context helper into a persistent memory runtime with durable trace evidence, per-turn path snapshots, graph data, and a static visual timeline.

## Approach

The existing runtime stays the center of gravity. `runtime.ts` will seed non-empty memory nodes, persist traces under `.orca-memory/traces`, maintain a compact table-based execution ledger, generate path snapshots under `.orca-memory/paths`, build graph data under `.orca-memory/graph`, and export `.orca-memory/visual/index.html`.

Existing CLI wrappers and plugin hooks remain compatible. New behavior is exercised through Node tests before runtime changes.

## Scope

- P0: non-empty memory init with frontmatter memory nodes.
- P1: persistent session traces with digests and relevance metadata.
- P2: path snapshots and latest pointer for each context plan.
- P3: graph data from memory, traces, and path snapshots.
- P4: static visualization export with timeline, path graph, detail, and diff panels.
- P5: lightweight backtrack candidates for repeated tool/target/digest reads.

## Testing

Tests cover init, trace, ledger, snapshot, graph, visual export, plugin trace capture, and compaction compatibility.
